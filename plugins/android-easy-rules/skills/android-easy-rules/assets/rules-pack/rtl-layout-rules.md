# Android 阿拉伯语 RTL 布局规则

## 默认触发与范围

- RTL-01：每次新增或修改 Android 布局代码，默认同时适配阿拉伯语 RTL，无需用户另行提醒。覆盖 XML、style、include/merge、弹窗/列表/分享布局、Kotlin/Java 动态布局、自定义 View/Canvas 和已有 Compose 布局；不因当前截图或系统语言为中文/英文而跳过。
- 只检查本次改动、必要父布局、绑定代码和公共组件受影响调用方；小改做对应检查，不升级为全仓迁移。明确的项目产品约定或用户豁免优先，记录例外范围与原因；不要把某项目的尺寸、阈值、周起始日或浮窗业务状态导出为通用默认值。
- 修改前核实实际布局方向来源、应用 `supportsRtl` 配置及局部方向覆盖。不得把所有页面强制设为 RTL，或用语言字符串硬编码判断替代实际 layoutDirection。已关闭 RTL 的项目先说明配置冲突，按现有配置修改权限处理。

## 布局、图标与动态代码

- RTL-02：阅读方向用 `start/end`：margin/padding、gravity、RelativeLayout 规则、ConstraintLayout 普通/gone margin 与约束、compound drawable、链及 barrier 等关联锚点一起检查。已有 start/end 属性与 left/right 冲突时核对运行值，不重复添加属性或机械覆盖。
- 动态代码同步使用相对 API，如 `setPaddingRelative`、`marginStart/marginEnd`、`Gravity.START/END`、相对 drawable 和逻辑约束；检查 adapter 绑定、状态切换、复用及分享离屏根布局。自绘坐标允许使用物理 X，但须依据语义转换。已有 Compose 使用逻辑 Alignment、start/end、相对 offset；不为 RTL 引入 Compose 或新依赖。
- 返回/前进、展开路径等方向性图标按语义镜像，可复用 `autoMirrored` 或 `drawable-ldrtl`；先看实际图形，再检查实际资源引用、动态 setImageResource 和 drawable 是否接收布局方向。不要仅凭文件名批量翻转，也不要叠加自动镜像和 scaleX 导致双重翻转。
- RTL-03：日历、星期排列与日期导航随 RTL，保持日期身份、既有周起始规则、前后日期含义及边界限制；核对自定义月历、旧 ViewPager 和独立星期栏，不假定库会自动正确镜像。聊天气泡/尾角/头像、输入与发送位置随方向，消息时间顺序不反转。
- 浮窗、侧栏或滑动控件按项目约定的起始侧/结束侧同步处理锚点、位移、速度、吸附和命中区域；核对正向、反向、取消、重复进入和方向变化。不能只移动图形而保留原手势方向。

## 需要保留方向的内容

- RTL-04：连续时间图表、睡眠时间轴、编辑范围默认保持 LTR，时间从左向右递增；只有明确产品约定才改变。局部图表、独立刻度及拖动命中保持一致，外层标题、导航、说明和图例仍随 RTL，不把整个页面锁为 LTR。
- Logo、照片、地图、设备示意、圆环和具有物理语义的表盘/相机坐标不整体镜像；需要固定方向时限制在最小子树。物理方向 API 的命中是待分类项，不自动视为错误或自动替换。
- WebView 原生外框与 H5 内容分别检查；无法维护的远端页面或仅有打包产物须记录边界。外框通过不能代表网页已完成 RTL。

## 文本与资源

- RTL-05：按实际绑定内容决定文字方向，不根据 `--`、`0`、日期等初始占位符推断该字段永远是数字。后续可能显示姓名、阿语说明或时长的 TextView 不统一固定 `textDirection=ltr`；按语义选择默认方向或 `firstStrongLtr`，保留阿语强字符判断与纯数字 LTR 回退。
- 邮箱、URL、MAC、版本和固定格式数字串按需要做最小方向隔离；混排可用 `BidiFormatter`，只作用于展示，不把方向控制字符写入存储、网络或设备协议。输入字段同时检查实际输入、阿语 hint、对齐和光标行为，不把“输入内容保持内部顺序”误当成“提示文字强制 LTR”。
- 不反转字符串/业务列表来模拟 RTL，不擅自改变数字字形、日期格式或评分阈值。新增/修改文案沿用多语言规则；阿语 key 审核排除 `translatable=false`，检查缺失、重复、格式参数及占位符，而不是用原始 key 数量差直接判缺译。
- 阿语长文案检查窄屏、大字体、换行、父子宽度与固定高度；必要时按控件语义使用自适应字号、最大行数或可滚动布局，不能为“截图不裁切”一律缩小正文或隐藏必要信息。日历/标题/按钮避让须同时检查 LTR 回归。

## 每次改动的完成检查

- RTL-06：完成前必须做改动范围内的 RTL 静态检查：布局/style 中 left/right 与固定方向、自定义/动态布局中的物理 API、方向性资源实际引用、绘制与触摸映射、文本实际绑定和资源引用；说明每个保留物理方向的合理例外。发现问题在本次授权范围内修复，不把检查留给用户额外提出。
- 使用当前 diff 加本次新增文件建立范围，勿遗漏未跟踪布局；不把其他人的未提交改动混入修复。静态检查覆盖 XML 解析、重复属性、资源存在与 LTR 行为；不只靠搜索零命中断言正确，也不通过盲目全量替换制造差异。
- 验证顺序沿用根规则和 testing-build-rules：先实现与最小静态检查，再根据本任务已有授权选择 Paparazzi、设备或仅静态。默认适配 RTL 不等于默认授权视觉测试、设备操作、新依赖或全量 Gradle；规则维护自身不运行 Android 构建。
- RTL-07：使用 Paparazzi 时显式检查 `supportsRtl = true`、`LayoutDirection.RTL` 和阿语 locale；仅切换 locale 可能只翻译文字，布局仍为 LTR。保留一个 LTR 对照，按实际容器继承方向，不递归强制覆盖应保留 LTR 的图表子树。
- 测试用实际资源和有代表性的数据；需要 parent、窗口或触摸分发的控件提供合理宿主。动画/翻月后完成布局再取稳定截图，不把回调改变但仍绘制旧帧的截图当成新状态。补充几何/交互断言：前后导航语义、选中日期、拖动边界、取消恢复；截图生成或新录 baseline 不等于视觉验收，必须实际查看。
- 交付分别报告静态、离屏组件、真实宿主与 H5 结果。未运行的语言切换重入、键盘、弹窗、聊天/分享宿主或设备场景明确标记未验证；不能用一次组件截图宣称所有页面 RTL 通过。

## 代表案例回放

| 场景 | 应采取的动作与可观察证据 |
| --- | --- |
| 新增普通 XML 页面，用户只给 LTR 设计 | 自动使用 start/end；定向检查动态绑定和方向图标，保留 LTR 对照 |
| 已有页面仅调一个间距 | 检查该控件和相关父/相邻锚点，不迁移整个仓库；有意物理间距说明原因 |
| 数字占位字段后来绑定阿语姓名/时长 | 阅读绑定位置，按强字符方向处理；不批量强制 LTR |
| 日期列表/日历 | 镜像列与点击映射，保持业务日期/周起始规则，复核翻月和取消 |
| 带非零数据的时间图表 | 图表局部 LTR、周边 RTL，绘制/刻度/选点/起止拖动一致 |
| 浮窗或聊天组件 | 核对结束侧停靠、手势速度/取消、气泡尾角与发送图标 |
| Paparazzi 阿语场景却仍是左侧返回 | 先查 RTL 支持与实际方向，修测试配置后重验，不先改生产代码硬翻转 |
| 小屏大字体或旧日历标题重叠 | 查父布局测量与 wrap_content/约束，固定数据重验阿语和 LTR |
| 仅静态授权或 H5 来源缺失 | 完成可做的适配与静态检查，明确剩余边界，不擅自探测设备或宣称已验收 |

此表用于主代理按本次实际改动回放决策；导入器测试只能证明规则可达、内容保留与幂等，不能证明未来所有智能体都会遵守或所有 App 视觉正确。
