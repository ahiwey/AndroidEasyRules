# Custom View / Chart Rules

## 适用范围

- Canvas 自定义 View
- 健康图表
- 睡眠、心率、血氧、血压、步数、温度、压力等趋势图
- 自定义进度、柱状图、折线图、饼图

## 修改前

- 新增 View、重做绘制结构或改变交互时，先找同类 View 对比并延续已有风格；明确的单个间距、尺寸、颜色或裁切问题只读取目标 View 和实际使用位置。
- 先理解数据输入、单位、时间范围、空数据处理和 UI 使用位置。
- 修改坐标前先写出最小“绘制契约”：有效绘图区边界、数值到坐标的唯一映射、网格线与数据点是否共用该映射、文字使用左/右锚点还是实际字形中心对齐。
- 把最小值、最大值、两位/三位刻度、单位切换、上下左右裁切列为同一组边界验收；修复一个锚点时不得破坏已经通过的锚点。
- 只有涉及调用链或共享绘制逻辑时，才使用 CodeGraph 查调用方和影响范围。
- 截图已明确指出局部问题时走 Quick：一次聚焦修改后优先做 diff 和边界计算检查，不加载通用 UI/UX 流程，也不默认运行 Gradle。
- 用户在上一轮修改后仍反馈错位或裁切时，先核对实际 View 尺寸、父容器 margin/padding/clip 和当前未提交差异；按用户已选的静态/Paparazzi/设备路径闭环，未授权不探测设备，不连续替换固定 offset 碰运气。

## 绘制规则

- `onDraw` 中避免频繁分配对象、解析资源、创建格式化器或做重计算。
- 复杂计算应提前缓存到字段、`onSizeChanged` 或数据设置阶段。
- Canvas 变换要配对 `save/restore`。
- 文字基线、clip、padding、圆角、线宽和密度换算要清晰。
- 同一轴的刻度线、曲线、填充和选中线应尽量复用同一个坐标函数；文字基线必须从 FontMetrics 或 glyph bounds 反算到目标视觉中心，不能直接把 baseline 画在网格线上。
- 必须处理空数据、单点数据、极值、单位切换、文字过长、左右边界、夜间/皮肤模式和不同屏幕宽度。

## 注释和测试

- timing、animation、smoothing、scaling、business rule 相关的非直觉逻辑，用简短英文注释解释原因。
- 图表纯计算逻辑可以隔离时，优先补聚焦单元测试。
- 实际绘制效果仍以截图或人工视觉验证为准。

## 图表视觉契约

- 编码前记录相关柱宽/柱距、平顶/圆顶/胶囊端帽、圆角上限、绘图区与基线、零值/缺失/小正值、颜色/渐变、轴刻度、网格/目标虚线、选中线及气泡数值/单位/时间。只写当前图需要的项，不生成重复报告。
- 进度条与数据柱不是同一种几何；strokeCap、最小高度或圆角会改变短柱与零值外观，必须以设计与业务语义为准，不盲目画点或抬高为非零柱。
- 零值与一组有高低/短柱的非零数据分开验收；全零/空图不能证明柱宽、端帽、间距、坐标和气泡符合设计。缺数据时标注非零形态未验证。
- 按截图专项规则询问仅静态/Paparazzi/设备验收；测试 fixture 只用于隔离测试，不写用户健康数据。Paparazzi 复用真实 View/资源，新录 baseline 必须查看并对照设计，不凭 verify 成功宣称还原。

- 缺失值不等于零值；是否跨缺失日期连接、目标线是否独立于实际数据，先查业务契约，图稿不能确定且影响实现时再询问，不规定所有图表统一断线或连线。交互图表核对横向选择与父容器纵向滚动；设置箭头、展开和提示气泡同属验收范围。
