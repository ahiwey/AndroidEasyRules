# Multilang String Rules

## 触发条件

- 新增、删除、重命名或修改字符串资源 key，检查字符串资源存放位置。
- 用户要求翻译、多语言同步、文案替换、品牌词替换、权限说明文案或多套 `values-*` 资源一致性。

## 执行方式

- 默认所有语言的 `res/values/` 与 `res/values-*`（含组合限定符目录）中的字符串资源只能放在各目录的 `strings.xml`；新增字符串一律写入该文件，文件不存在时创建，不向其他 XML 追加。
- 字符串资源任务开始时，在目标模块和 source set 范围内检查上述目录的 XML；识别 `<string>`、`<item type="string">`，以及承载文本的 `<plurals>`、`<string-array>`，不要把 style 的 `<item>` 或颜色、尺寸等非字符串资源误报。每个任务检查一次，不因单 key 修改扩大为全量翻译审计。
- 发现其他 XML 中含有字符串资源时，告知用户文件路径、资源类型和 key；不擅自迁移、重命名或删除。仅修改既有 value 时保留原位置并报告；新增 key 仍写入 `strings.xml`，先确认同目录其他 XML 中没有同名同类型资源，避免重复定义。
- 已知 string key 时，优先用结构化 XML 解析或复用脚本批量更新目标语言的相关资源，按需同步本次涉及的限定符覆写；发现既有资源在其他 XML 时按上一条处理，不漏改目标 key；不要手工逐个 patch 大量语言文件。
- 批量更新只修改目标 key，不重排无关资源，不格式化整个 XML。
- 可复用脚本时优先放在 `tools/` 等明确工具目录；临时脚本只用于一次性迁移，执行后删除并检查状态。

## 同次本地化

- 新增可翻译资源或修改默认文案时，同次完成目标语言的翻译或复核。按本次差异列出资源类型、key 和目标语言。源文存在拼写、术语或语义疑点时，先按产品说明、实际调用或已有术语确认，再批量同步。
- 按目标模块、source set 和实际发布变体识别目标语言，核对地区或语言脚本继承及有效的资源定义。`values-v21`、`values-sw*dp`、`values-night` 等非语言限定目录只核对相关覆盖，不计入语言覆盖率。遵循项目明确的地区覆写、回退与 `translatable="false"` 约定。
- 逐个 key 和目标语言核对译文已新增、已更新、经复核可沿用，或属于用户确认的例外。非目标语种中沿用明显未翻译的默认原文，或默认文案的拼写、术语、语义变更后原译文保持不变，均需复核。合法同形的品牌、专名、缩写、单位、空值和资源引用按语义保留；仅同值或仅有非空值都不能证明翻译已完成。临时回退、延期或跳过翻译须经用户明确确认，按 key 和语言列明依据与未完成项，不把占位计入完成数。

## 资源类型与历史兼容

- 以资源类型和 key 双向对照有效默认资源与目标语言，核对缺失、重复和仅在语言目录定义的 key。发现缺少默认定义时先查是否有可用默认来源、调用方和有意例外，并报告存量问题。验收以本次新增或改动为主，有证据再扩大范围。
- `<string>`、`<item type="string">`、文本 `string-array` 和 `plurals` 都要验证内容、格式参数、内联标记及转义。数组按项核对数量、顺序和位置语义，复数核对目标语言适用的分支、`other` 和参数契约。若工具只分析普通 `<string>`，额外对本次涉及的数组、复数或别名定义做结构化 XML 核对，再汇总证据。
- 展示文案参与持久化、匹配或序列化时，先核对实际读写和展示调用方。使用稳定标识与本地化展示文案的映射；已有数据按已知历史值兼容，保留未知或自定义值，覆盖新记录、旧记录与切换语言后的回显。历史文本有歧义时明确报告，保留数组位置或已有标识契约。

## 单 key Quick 路径

- 满足项目方案门四项条件，并在写入前说明具体改动后，可在以下场景走 Quick：用户给出 1–3 个准确且已存在的 key；任务只改 value，不新增、删除、重命名或排序 key；占位符、内联标签和 XML 结构不变；当前没有缺 key、重复 key、乱码或解析异常证据。
- Quick 最多执行一次目标 key 定向检索、一次批量改值和一次轻量验证；不要为统计整个资源集运行全量 audit 或 sort，不生成独立计划文档，也不运行 Gradle。
- 按同次本地化要求定向复核。轻量验证只检查目标 key 的语言覆盖、译文内容和唯一性、变更文件 XML、占位符及改动范围，并运行 `git diff --check`。
- 任一目标语言缺 key、出现重复或解析失败、占位符/内联标签变化、编码异常或意外文件差异时，退出 Quick，先做只读审计，后续写入按方案门处理。

## 品牌词与旧词扫描

- 权限和设备相关文案重点检查：`戒指`、`设备`、`ring`、`device`、`watch face`、`表盘`、`錶盤`。
- 只扫描目标 key 的 value，避免 XML 标签名或其他无关文案造成误判。
- 涉及品牌词时，按当前分支品牌语义统一，不从其他品牌分支复制不适配文案。

## 默认验证

- 存放位置：确认新增字符串仅落在各目录的 `strings.xml`；其他 XML 中已有字符串的路径、类型和 key 已告知用户，未擅自迁移。
- key 与译文验收：确认本次 key 的默认定义和目标语言覆盖，逐语言核对翻译或复核结果，列明例外和存量发现。
- 旧词残留：确认目标 key 的 value 中没有本次要求替换掉的旧词。
- 现有 key 的 value 调整使用 XML 解析、覆盖率和差异检查，不默认运行 Gradle。
- 新增/删除/重命名 key 或资源引用时，最多运行一次受影响模块的最小资源处理任务；只有需要 APK/AAR 产物或打包集成验证时才运行 assemble。
- `git diff --check`：确认没有 XML 空白问题。
