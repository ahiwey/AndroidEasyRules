# Multilang String Rules

## 触发条件

- 新增、删除、重命名或修改字符串资源 key，检查字符串资源存放位置。
- 用户要求翻译、多语言同步、文案替换、品牌词替换、权限说明文案或多套 `values-*` 资源一致性。

## 执行方式

- 默认所有语言的 `res/values/` 与 `res/values-*`（含组合限定符目录）中的字符串资源只能放在各目录的 `strings.xml`；新增字符串一律写入该文件，文件不存在时创建，不向其他 XML 追加。
- 字符串资源任务开始时，在目标模块和 source set 范围内检查上述目录的 XML；识别 `<string>`、`<item type="string">`，以及承载文本的 `<plurals>`、`<string-array>`，不要把 style 的 `<item>` 或颜色、尺寸等非字符串资源误报。每个任务检查一次，不因单 key 修改扩大为全量翻译审计。
- 发现其他 XML 中含有字符串资源时，告知用户文件路径、资源类型和 key；不擅自迁移、重命名或删除。仅修改既有 value 时保留原位置并报告；新增 key 仍写入 `strings.xml`，先确认同目录其他 XML 中没有同名同类型资源，避免重复定义。
- 已知 string key 时，优先用结构化 XML 解析或复用脚本批量更新所有目标模块现有 `values*/strings.xml`；发现既有资源在其他 XML 时按上一条处理，不漏改目标 key；不要手工逐个 patch 大量语言文件。
- 批量更新只修改目标 key，不重排无关资源，不格式化整个 XML。
- 默认 `values/strings.xml` 与所有已有 `values-*` 下同名 key 同步；用户明确要求跳过翻译时，最终回复必须说明未同步范围。
- 可复用脚本时优先放在 `tools/` 等明确工具目录；临时脚本只用于一次性迁移，执行后删除并检查状态。

## 单 key Quick 路径

- 同时满足以下条件时走 Quick：用户给出 1–3 个准确且已存在的 key；任务只改 value，不新增、删除、重命名或排序 key；占位符、内联标签和 XML 结构不变；当前没有缺 key、重复 key、乱码或解析异常证据。
- Quick 最多执行一次目标 key 定向检索、一次批量改值和一次轻量验证；不要为统计整个资源集运行全量 audit 或 sort，不生成独立计划文档，也不运行 Gradle。
- 轻量验证只检查目标 key 在默认与现有语言目录中的覆盖率和唯一性、变更文件 XML 可解析、占位符保持一致、变更集合只含目标 value，并运行 `git diff --check`。
- 任一目标语言缺 key、出现重复或解析失败、占位符/内联标签变化、编码异常或意外文件差异时，退出 Quick 并升级到完整多语言审计流程。

## 品牌词与旧词扫描

- 权限和设备相关文案重点检查：`戒指`、`设备`、`ring`、`device`、`watch face`、`表盘`、`錶盤`。
- 只扫描目标 key 的 value，避免 XML 标签名或其他无关文案造成误判。
- 涉及品牌词时，按当前分支品牌语义统一，不从其他品牌分支复制不适配文案。

## 默认验证

- 存放位置：确认新增字符串仅落在各目录的 `strings.xml`；其他 XML 中已有字符串的路径、类型和 key 已告知用户，未擅自迁移。
- key 覆盖率：确认目标 key 在默认和所有现有 `values-*` 目录中存在或按任务要求缺失。
- 旧词残留：确认目标 key 的 value 中没有本次要求替换掉的旧词。
- 现有 key 的 value 调整使用 XML 解析、覆盖率和差异检查，不默认运行 Gradle。
- 新增/删除/重命名 key 或资源引用时，最多运行一次受影响模块的最小资源处理任务；只有需要 APK/AAR 产物或打包集成验证时才运行 assemble。
- `git diff --check`：确认没有 XML 空白问题。
