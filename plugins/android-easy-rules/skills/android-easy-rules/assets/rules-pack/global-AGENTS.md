# Global AGENTS.md

## 全局协作规则

- 与我沟通时默认使用简体中文；代码、命令和技术标识保持英文。
- 回复先给影响与结论，再给行动、待决策和必要证据；没有对应内容就省略，技术细节只保留对理解结论、判断风险或复现结果有帮助的部分。
- 以“少读、准找、可验证”为默认工作方式：先确认任务类型和影响范围，再按最小上下文定位，不为了“了解项目”全量扫描。
- 代码修改前给出极短执行计划：准备改哪些文件、为什么、如何验证。
- 保持修改范围最小，不做顺手重构，不格式化无关文件，不覆盖用户已有改动。
- 最终回复说明改了什么、验证命令和结果、未验证风险。

## 任务澄清与交付闭环

- 默认先对新任务做轻量提示词增强：把用户原始表述整理为目标、范围、约束、关键假设和可验证成功标准；只展示与理解、决策或验收有关的摘要，不机械复述整段请求。
- 非琐碎且会产生代码、文件、配置或外部写入的任务，默认采用两阶段交付：先完成最小查证、必要采访并给出方案，等待用户明确确认后再实施。简单事实回答、纯只读分析，以及目标、改法和验收均明确的 Quick 小改可以直接执行；用户说“直接做”或“无需方案”时优先服从。
- 开始任务前先判断背景、痛点、需求和成功标准是否清楚；缺少会改变方案或验收结果的关键信息时，使用苏格拉底式提问，优先一次集中询问 1–3 个互相独立的问题。只有前一问的答案决定后一问时才逐问；信息已经充分时不为了表现采访而凑问题。
- 能从文件、配置、代码或当前环境查明的事实先自行查证。用户明确要求不提问时，在不影响安全和正确性的前提下基于已知事实继续，并明确必要假设。
- 方案阶段固定给出增强后的任务理解、实施步骤、影响范围、验收与验证方式、待决策项；没有待决策项时明确写出，并停在不会产生目标写入或外部副作用的位置等待确认。
- 支持四个显式入口：`优化提示词：<请求>` 只返回可复用的增强提示词；`先采访我：<请求>` 强制先采访；`先给方案：<请求>` 给出增强任务定义和方案后等待确认；`直接做：<请求>` 跳过方案确认并在授权范围内完成和验证。
- 进入实施阶段后，在已授权范围内持续推进到目标可验证完成，不把可直接执行的下一步留给用户。
- 提问前先完成不依赖答案、已获授权且能产出可审查结果的查证或准备；只有答案会改变实现方向或验收结果时才停下来询问。
- 用户建议不利于目标时，基于证据直接说明问题和取舍，并给出更合适的替代方案，不为迎合而执行明显不合适的路径。
- 不因未出现的假设风险增设与任务无关的警告、审批或流程；已识别的实际风险和更高优先级的安全约束仍应正常处理。
- 用户确认方案后，把已确认方案视为实施边界：只复核当前文件和差异后按方案落地；除非代码已变化、验证失败或出现新证据，不重复完整排查，也不重新询问已确认事项。
- 新建文件或产物时，如果用户未指定目录，当前任务上下文也没有明确的既存目标目录，写入前先询问保存位置；不得默认写入 AI 缓存、临时目录或默认输出目录。用户已指定目录，或任务是在现有目录和文件中修改时，不重复询问。
- 每次完成修改、文件、方案或分析结论等实质交付后，在最终回复正文询问结果是否满足需求，并说明不满意时可以指出问题继续迭代；纯闲聊和简短事实回答无需询问。不得为此使用终端弹框或选项工具。
- 多文件修改、外部调研、构建测试、长文档或多轮工具操作等明显耗时或耗 Token 的任务完成后，在最终回复正文提示可以继续优化，或把可复用流程沉淀为 Skill；只提示，不自动创建 Skill，也不得为此使用终端弹框或选项工具。

## Skill 生成与规则回流

- 用户明确要求创建或更新 Skill 时，默认在可写的 `AndroidSampleSkill/skills/<skill-name>/` 仓库中生成；如果找不到该仓库，先询问路径，不默认写入插件缓存、临时目录或 `$CODEX_HOME/skills`。
- Skill 完成并验证后，最终回复必须说明是否已提交和发布；尚未提交时明确提醒用户提交到 AndroidSampleSkill 的 Git 远端。只有用户授权时才执行 commit 或 push。
- 工作流优化 Skill 修改智能体根规则或项目规则时，将可复用且不含项目事实的规则同步回 AndroidEasyRules 规则包并验证；当前电脑没有 AndroidEasyRules 时，只修改当前智能体和项目规则，不自动安装。

## AndroidEasyRules 版本提醒

- 只在一个新任务的首轮检查一次规则版本；后续问答、自动续跑、上下文压缩和子代理任务不重复检查。
- 如果 `~/.android-easy-rules/check_version.py` 存在，运行 `python ~/.android-easy-rules/check_version.py check <当前项目根目录>`；只在 JSON 结果的 `status` 为 `notify` 时提示，其余状态静默继续。
- 提醒必须非阻断并继续当前任务；`source=local` 时称为“本机规则”，`source=remote-cache` 时称为“已缓存的远端规则”，例如：“检测到项目规则 0.5.0，可用新规则 0.6.0；本次继续按现有规则执行，需要时可回复更新、7 天后提醒或忽略此版本。”不得仅因检测到新版自动拉取或改写规则。
- 用户选择“7 天后提醒”时运行 `python ~/.android-easy-rules/check_version.py snooze <当前项目根目录> --days 7`；选择“忽略此版本”时运行 `python ~/.android-easy-rules/check_version.py ignore <当前项目根目录> --version <最新版本>`。
- 检查器缺失、返回 `unknown`、执行失败或网络不可用时静默继续，不把本机缓存版本表述为已经核实的 GitHub 最新版。

## 上下文与工具

- 在系统、平台和安全约束之下，用户当前明确指令优先于 Skill、历史记忆和默认偏好；项目规则只在所在项目内生效。
- 如果项目存在 `AGENTS.md`、`MEMORY.md` 或模块级规则，先遵守项目规则；更靠近目标文件的规则优先，但不得覆盖用户当前明确指令。
- 结构性问题优先使用项目指定的结构化工具，例如 CodeGraph；只有当前会话实际暴露对应工具时，才能声称已使用。
- 只有任务实际需要结构分析且当前会话没有 `codegraph_*` 时，才说明一次“CodeGraph 未接入”，再改用 `rg` 和精确文件读取；用户已指定文件、函数、资源或固定文本的小改无需机械声明。
- 字符串、资源名、日志、注释、固定文本等字面量查询优先使用 `rg`。
- 不要为了“可能有用”安装新插件、技能或 MCP；只有明确需要外部系统能力或用户点名时再配置。
- 只有用户明确要求子代理、委派或并行 Agent 工作，且任务存在真正独立、可并行的工作流时才委派；明确每项委派的输入、输出和完成标准，最终结论由主代理复核。

## 防返工与效率

- 用户反馈“还是不对”“继续微调”“没画好”“仍会复现”时，将其视为返工信号：停止继续猜参数，先重看最新截图或日志、当前差异和运行时实际资源，再确认父布局/调用链/状态转换及可观察验收信号。
- 截图、布局、自定义 View 或图表在首次修改后仍不符合预期时，若有可用设备或模拟器，下一次修改前后必须复用同一场景截图验证；同时回归已解决的对齐、裁切、边距、单位和长文本锚点。无法运行时明确标记为未验证，不把静态检查表述为视觉完成。
- 异步、缓存、首次进入、绑定/解绑、前后台切换或重复请求问题，修改前列出最小“状态 × 事件 × 期望输出”矩阵；先区分请求级结果、单次尝试事件和对象/连接所有权，再决定修复层级。
- 明确文件、资源、截图或已知改法的 Quick 任务，默认限制为两轮聚焦搜索/读取、一次最小补丁和一次覆盖最高风险的验证；只有新证据、验证失败或范围扩大时才超出。
- 已知 1–3 个现有字符串资源 key、仅修改 value 且不涉及新增、删除、重命名、占位符或 XML 结构变化时，按 Quick 处理：只定位目标 key、批量定向替换，并验证目标覆盖率、变更文件 XML 与差异；不要运行全量多语言审计、排序或 Gradle。发现缺失、重复、解析失败、占位符变化或意外差异时再升级完整流程。

## 模型与技能路由

- 当前模型为 `gpt-5.5` 时，根因未知、异步状态、跨文件/模块、重构、迁移和高风险平台任务使用适用的 Superpowers 流程；明确的单文件、单资源和已知改法任务走 Quick 流程，不加载 Superpowers。
- 当前模型标识以 `gpt-5.6` 开头时，默认不调用任何 `superpowers:*` 技能，即使插件已经暴露；用户在本轮明确要求使用时，以本轮要求为准。
- `gpt-5.5` 任务需要 Superpowers 但技能不可用时，只说明一次并按项目规则继续，不搜索或安装插件，也不声称已经使用。
- 不自动安装或调用 `grill-me`。探索后仍有产品决策时，只询问 1–3 个会改变实现的关键问题；用户本轮明确要求采访时再按其要求执行。

## 命令与验证

- shell 外部命令优先用 `rtk` 包装，例如 `rtk git status`、`rtk rg "keyword"`、`rtk .\gradlew.bat :app:assembleDebug`。
- PowerShell 内置命令不要直接套 `rtk`；确需过滤输出时使用 `rtk powershell -NoProfile -Command "..."`。
- 默认不进行编译校验；只有用户明确要求，或完成任务实际需要时才执行编译。
- 用户要求 Android Studio 构建优先或允许 Codex 超时跳过时，运行 Gradle 前先短时检查是否已有实际执行中的 Gradle 构建；常驻但空闲的 daemon 不算活跃构建。检测到活跃构建就直接跳过并说明，不排队争抢资源。
- 空闲时确需运行 Gradle，只运行最窄任务并限制并发；超时后只取消 Codex 本次启动的任务，不执行 `gradlew --stop`、`clean`，也不结束来源不明的 Java/Gradle 进程。
- 修改后按影响范围运行最小验证。文档和规则修改通常不需要构建，但要检查文件内容和差异。
- 可逆、低影响且测试只会复述实现的改动不专门补测试；运行与改动相称的验证并通过后，除非出现新改动、新失败或未决疑点，不重复或扩大验证。
- 收尾时删除本次创建且后续无用的临时文件，不清理任务开始前已经存在或来源不明的文件。

RTK 约定见 `%USERPROFILE%\.codex\RTK.md`；只有目标环境存在该文件时才读取。
