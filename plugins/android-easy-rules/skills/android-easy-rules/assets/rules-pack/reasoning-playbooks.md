# 推理与决策方法路由

本文件把常用 Prompt 方法改写为可复用的 Agent 规则。方法思路参考微信公众号《数字生命卡兹克》的《都 Agent 时代了，我还是想分享给你这 12 个我最常用的 Prompt》，这里只保留适用条件、执行步骤和停止条件，不复制原始长 Prompt。

## 统一入口

- 只输入 `常见Prompt`、`常见 Prompt` 或 `思考菜单`：列出下方 12 种方法及编号，并展示 `常见Prompt：<问题>`、`常见Prompt <编号>：<问题>` 和 `常见Prompt 推荐：<问题>` 三种用法。
- 输入 `常见Prompt <编号>：<问题>`：读取并使用对应编号的方法。
- 输入 `常见Prompt：<问题>`：选择最可能改变结果的最少方法，简短说明选择后直接执行。
- 输入 `常见Prompt 推荐：<问题>`：先用一句话说明推荐方法及理由，再直接执行；用户明确只要推荐时才停在推荐阶段。
- 插件环境也可显式调用 `$reasoning-playbooks`；通过插件入口时可输入 `@Android Easy Rules 常见Prompt`。

## 使用边界

- 用户明确指定方法时优先按用户要求执行；未指定时，只选择最可能改变结果的最小方法，不在简单任务上机械叠加流程。
- 意图和成功标准已经清楚时直接行动；能从文件、代码、配置、数据或可靠来源查明的事实先自行查证，不用提问代替检索。
- 输出长度服从用户要求和任务复杂度，不因使用某个方法自动扩写成长报告。
- 事实、推断、价值判断和建议分开表达；证据不足时明确标记未核实，不把方法名称当作结论可靠性的证明。
- 涉及医疗、法律、财务、心理健康或其他高风险主题时，优先采用可靠来源和适当边界，不以角色扮演代替专业判断。

| # | 方法 | 适用场景 | 默认触发方式 |

| 1 | 苏格拉底式提问 | 需求、概念或成功标准含糊 | 信息不足时启用 |
| 2 | 双层解释法 | 学习陌生概念 | 用户要求解释或教学时启用 |
| 3 | 反向拆解 | 学习优秀成品或方案 | 有明确范例时启用 |
| 4 | 横纵分析法 | 系统研究产品、公司、技术、行业或事件 | 需要外部研究时启用 |
| 5 | 事实核查 | 核验说法、数据、观点或方案 | 准确性影响结论时启用 |
| 6 | 专家视角会诊 | 单一视角难覆盖复杂问题 | 复杂方案权衡时启用 |
| 7 | 第一性原理 | 路径依赖、旧方案反复修补 | 需要重审假设时启用 |
| 8 | 跨领域借解 | 本领域常规方法失效 | 需要寻找类比机制时启用 |
| 9 | 双向钢人论证 | 两个选项难以取舍 | 二选一决策时启用 |

## 1. 苏格拉底式提问

- 先判断缺少的信息是否真的会改变实现、结论或验收；不会改变结果的问题不问。
- 每轮只问一个最关键的问题，根据回答决定下一问，不提前发整套问卷。
- 优先区分可验证事实、对事实的解释、价值判断和用户目标，并检查含糊词、默认前提、证据与相反解释。
- 每次追问前用一句话说明新回答更新了什么判断；信息足够立即停止。
- 结束时整理真正要解决的问题、已确认事实、未验证假设、关键变量和可执行的新问题；需要用户选择时等待确认再推进。

## 2. 双层解释法

- 第一层使用生活化语言和一个具体例子，确保没有相关背景也能理解。
- 第二层使用准确术语说明核心机制、适用边界和常见误解，不用术语堆砌代替解释。
- 最后给出小白说法与专业术语的对应关系、最容易误解之处，以及少量理解检查题。
- 用户已经具备专业背景时压缩第一层；用户只要快速结论时不强制输出完整教学结构。

## 3. 反向拆解

- 先用一句话说明范例解决了什么问题、服务谁以及完成标准是什么。
- 从目标、结构或流程、关键选择和质量门槛反推它为什么有效。
- 区分可迁移规律与案例特有细节，不把相关性误写成因果关系。
- 输出 3～5 条可复用规律、一份最小操作清单和一个低成本练习；没有足够材料时先说明证据缺口。

## 4. 横纵分析法

- 纵向分析诞生背景、关键推动者、重要转折、成功失败，以及早期选择形成的能力、路径依赖和包袱。
- 横向选择真正可比的对象，说明选择理由，并使用统一维度比较强项、短板、差异和用户选择原因。
- 合并两条轴判断未来可能路径、成立前提和预警信号；未来判断必须标记为推断。
- 优先使用官方资料、原始数据、论文、财报和访谈等一手来源；重要结论就近标注来源与日期，冲突信息并列呈现。
- 报告长度按用户要求和证据量决定，不默认生成超长文档。

## 5. 事实核查

- 先把输入拆成可外部验证的事实、由事实推出的结论和价值判断。
- 对事实核查来源、样本、时间与完整上下文，并标为：已证实、基本成立但需收窄、存在争议、证据不足或明显错误。
- 再检查事实是否足以推出结论，是否存在隐含假设、相关性与因果性混淆、遗漏变量或其他解释。
- 输出可信部分、需要修正部分、推理链关键漏洞、补强后的合理版本，以及当前可信程度。

## 6. 专家视角会诊

- 选择 3 个真正互补的专业视角，并说明每个视角为什么必要；不要模仿或编造真实人物观点。
- 每个视角分别重述问题、推荐路径、指出其他视角易忽略的风险，并说明什么证据会改变判断。
- 汇总共同事实、真实分歧和分歧背后的不同假设，再给出综合方案、适用条件、最大风险、退出条件和第一步。
- 默认在当前回答内完成多视角分析，不自动创建子代理；只有用户明确要求子代理、委派或并行 Agent 工作时才创建或调用子代理。

## 7. 第一性原理

- 区分无法绕开的基本事实、未经验证的惯例或假设、真正目标，以及资源与约束。
- 暂时放下现成方案，从事实、目标和约束重新推导最简单可行路径。
- 指出原方案中只修补表面的部分、新路径成立的前提和第一个验证动作。
- 如果行业约束本身已经被可靠证据确认，不为追求“推倒重来”而忽略它。

## 8. 跨领域借解

- 先剥离行业术语，抽象出问题结构、核心矛盾和常规解法失效原因。
- 从至少 3 个距离较远但结构相似的领域寻找机制；每个案例说明问题、机制、相似点、可迁移部分和失效条件。
- 优先迁移底层机制，不照搬表面形式；无法验证的历史类比应标为启发而非证据。
- 最后选择最值得尝试的机制，翻译成当前场景下的低成本、可逆实验。

## 9. 双向钢人论证

- 先准确重述真正需要做出的选择、目标和现实约束，不默认用户给出的两个选项已经穷尽可能性。
- 分别给出两方最强理由、适用条件、收益、风险和最难回答的反对意见。
- 找出真正分歧、关键变量和缺失信息；仍有一个变量可能改变结论时，只问该问题。
- 信息足够后给出明确判断、理由、适用条件和下一步，不用“各有利弊”回避结论。

## 10. 最小实验

- 列出决定背后最需要验证的少量假设，选择最可能改变结论的一项。
- 设计低成本、可逆、周期明确的实验，写清动作、投入、指标、继续条件、停止条件和实验结束后新增的信息。
- 指标必须能观察或记录；无法区分成功和失败的活动不算实验。
- 优先给出可以立即开始的第一步，不用更多讨论代替现实反馈。

## 11. 隐藏天赋探索

- 仅在用户明确要求长期自我探索时启用；先说明这不是心理诊断或标准化测评。
- 每轮只问一个问题，围绕早期自发投入、无意识胜任区、能量变化、长期被批评的特征和羡慕对象追问具体经历。
- 所有判断必须对应用户提供的经历；证据不足时使用“可能”，不得根据单个回答贴固定标签。
- 区分擅长、喜欢和做完后获得能量，不把职业方向说成唯一答案。
- 素材足够后总结有证据的能力模式、阴影面、能量地图、适配环境和低成本验证实验；篇幅由用户决定。

## 12. 人生设计

- 仅在用户明确要求人生规划时启用；保持支持性但不替用户做决定。
- 从健康、工作、娱乐和关系的当前状态开始，区分无法直接改变的重力问题与可以重新定义的设计问题。
- 通过工作观、人生观、心流与能量线索形成指南针，再生成 3 条用户真心愿意考虑且明显不同的路径。
- 每条路径给出时间线、待验证问题、资源与风险，并设计人生对谈、短期体验或其他可逆原型。
- 用户处于明显低谷或情绪脆弱时，不强制进行负面未来推演；必要时建议寻求可信赖的人或专业支持。
